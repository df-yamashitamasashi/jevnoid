# Thomas S. Ray (1990) Tierra 完全準拠仕様書

本仕様書は、1990年〜1991年にトーマス・S・レイ（Thomas S. Ray）が発表した人工生命システム **「Tierra（ティエラ）」** の原著論文（*Artificial Life II*, 1991 等）の思想、計算機工学的メカニズム、および進化的生態系の研究成果を100%現代的に完全網羅・再定義するものである。

## 1. Tierra 原著研究の 8 大核心要素と完全対応マトリクス

| # | Tierra 原著コア要素 | 原著の学術的定義 | Jevnoid 現代版での実装仕様 |
|---|---|---|---|
| 1 | **共用メモリ空間 (The Shared Soup)** | 全生物が単一の連続アドレス空間（RAM）に同居。メモリの重複・隣接により相互作用が生じる。 | 各ワールド（Theos, Gaia, Cosmo, Info）ごとに独立した共用RAMスープ（1024〜2048セル）を配備。全生物が同一スープ上に共存。 |

| 5 | **CPUスライサー (The Slicer / Time Sharing)** | スープ内の全生物に公平またはゲノムサイズに応じたCPUサイクルをラウンドロビンで割り当てる。 | ワールド内の全個体コンテキスト（レジスタ・IP・スタック）を順繰りにステップ実行するラウンドロビンスライサー。 |

| 8 | **進化的動態と多様度メトリクス (Macro-evolution & Diversity)** | 祖先種（Ancestor）、寄生体（Parasite）、免疫ホスト（Immune host）、超寄生体（Hyper-parasite）の共進化動態。 | シャノン多様度指数（Shannon Diversity Index）、寄生率（Parasite Ratio）、世代深度、リアルタイムゲノムマップの提供。 |

## 2. Tierra 32命令セット（Tierra-32 ISA）完全仕様

オペランドはすべて5ビット（0〜31）でエンコードされ、ハードコードされた数値アドレスは存在しない。

```
[0x00] NOP_0   : テンプレート探索用ビット 0
[0x01] NOP_1   : テンプレート探索用ビット 1 (NOP_0 と相補的)
[0x02] OR1     : BX = BX | 1
[0x03] SHL     : CX = CX << 1
[0x04] ZERO    : CX = 0 (Zero Flag = True)
[0x05] IFZ     : Zero Flag が True の場合のみ次命令を実行、False なら次命令をスキップ
[0x06] SUB_AB  : CX = AX - BX
[0x07] SUB_AC  : AX = AX - CX
[0x08] INC_A   : AX = AX + 1
[0x09] INC_B   : BX = BX + 1
[0x0A] DEC_C   : CX = CX - 1 (CX == 0 なら Zero Flag = True)
[0x0B] INC_C   : CX = CX + 1
[0x0C] PUSH_AX : AX をスタックにプッシュ
[0x0D] PUSH_BX : BX をスタックにプッシュ
[0x0E] PUSH_CX : CX をスタックにプッシュ
[0x0F] PUSH_DX : DX をスタックにプッシュ
[0x10] POP_AX  : スタックから AX にポップ
[0x11] POP_BX  : スタックから BX にポップ
[0x12] POP_CX  : スタックから CX にポップ
[0x13] POP_DX  : スタックから DX にポップ
[0x14] JMP     : 直後のテンプレートの相補パターンを前方探索し、IP をその位置へジャンプ
[0x15] JMPB    : 直後のテンプレートの相補パターンを後方探索し、IP をその位置へジャンプ
[0x16] CALL    : 次アドレスをスタックに保存し、テンプレートの相補先へジャンプ
[0x17] RET     : スタックからリターンアドレスをポップして復帰
[0x18] MOV_CD  : DX = CX
[0x19] MOV_AB  : BX = AX
[0x1A] MOV_IAB : スープの [AX] 番地のバイトを [BX] 番地へコピー（コピーエラー確率適用）
[0x1B] ADR     : 最寄りの相補テンプレートを探索し、そのアドレスを AX に格納
[0x1C] ADRB    : 後方に向かって相補テンプレートを探索し、そのアドレスを AX に格納
[0x1D] ADRF    : 前方に向かって相補テンプレートを探索し、そのアドレスを AX に格納
[0x1E] MAL     : 長さ CX の娘個体用メモリブロックをスープに確保し、その先頭アドレスを AX に格納
[0x1F] DIVIDE  : 確保した娘個体を自立生命体としてスープに登録（親と娘を完全分離）
```

## 3. 相補的テンプレートマッチングのアルゴリズム

Tierra の本質は、**生物が自分の開始・終了・サブルーチン・ループ先を数値ではなく「DNAの塩基配列のように相補的な並び」で探索すること**にある。

- `NOP_0` (0) の相補は `NOP_1` (1)
- `NOP_1` (1) の相補は `NOP_0` (0)

例：
```
探索元 (探すパターン): [NOP_0, NOP_1, NOP_0, NOP_0]
相補ターゲット:         [NOP_1, NOP_0, NOP_1, NOP_1]
```
探索命令（`ADRF`, `ADRB`, `JMP`, `CALL` 等）の直後に連続する NOP 列をパターン長 $L$ として抽出し、メモリ空間を探索。最も近い相補ターゲットの直後をターゲットアドレスとする。

## 4. 寄生（Parasitism）の生物学的成立メカニズム

1. **祖先（Ancestor-80）の構造**:
   - ヘッダテンプレート
   - サイズ測定コード（先頭と末尾のテンプレート間距離を算出）
   - メモリ確保コード (`MAL`)
   - **コピーサブルーチン** (`MOV_IAB` ループ)
   - 分裂コード (`DIVIDE`)
2. **寄生体（Parasite, 例: 45バイト）の構造**:
   - 突然変異により、**コピーサブルーチン（20〜30バイト）をごっそり欠落**させた個体。
   - 自身の体内には `MOV_IAB` を持たない。
   - その代わり、**祖先のコピーサブルーチンを指す相補テンプレートへ `CALL` または `JMP` する**。
   - 祖先（Host）のメモリ領域にあるコードを「借りて実行」し、自分自身の45バイトを娘領域へコピーさせる。
   - サイズが小さいため、祖先の約半分のCPUサイクルで自己複製を完了し、爆発的に増殖する。
3. **免疫ホスト（Immune Host）とハイパーパラサイト（Hyper-Parasite）**:
   - 寄生体の蔓延により、祖先はテンプレートを変更して寄生体を拒絶（免疫化）。
   - 寄生体のコードを逆利用して自身の複製を加速するハイパーパラサイトが自然創発する。

## 5. 死神（Reaper）アルゴリズム

スープの容量（Total Soup Memory）に対する使用率が **75%** を超えた場合、以下の基準で Reaper キューを評価する：
$$\text{ReaperScore} = \text{AgePulses} \times 1.0 + \text{ErrorCount} \times 10.0 - \text{Energy} \times 0.2$$
スコアが最も高い（高齢で、命令実行エラーや保護違反を多発させた）個体を終了（Reap）し、そのメモリ領域を未割当（Free）にして背景ノイズに戻す。
