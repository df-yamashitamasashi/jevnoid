## 2. Jev (System One) コスト最適化 & 思考モデル設計

### 2.1 心拍と Jev 呼び出し
1. **全個体一括の心拍**:
   - EventBridge `rate(3 hours)`（1日8回）で、生きている全個体が毎回1歩ずつ進む。個体数が増えても1体あたりの成長速度は変わらない。
2. **一括問い合わせ**:
   - 全個体の判断を1回の `system_one` 呼び出しにまとめる（`state` に `organism_0`, `organism_1` … を並べ、質問で対象を名指しする）。
   - 1心拍あたりの Jev 呼び出しは最大2回（行動判断 / 形態成長＋次の移動先）で、個体数に依存しない。トークン量は判断する個体数に比例する。
3. **満腹時のスキップ**:
   - `energy >= 85`・空腹度 `<= 0.15`・細胞6以上の個体は、Jev を呼ばずに瞑想する。
4. **誕生の抑制**:
   - Tierra VM の `DIVIDE` かつ成熟（エネルギー65以上・細胞3以上）でも、誕生は確率 0.5% のみ。さらに1世界あたり24時間に1体までを上限とし、同じ心拍で同じ世界に2体生まれることはない。

### 2.2 Jev 思考判断
* **`decide_actions` (Choice/Noul)**: 全個体の行動を一括判断
  - `ingest_nourish`: 高栄養知覚 ➔ 摂食と同化
  - `swim_next`: 次の知の海へ移動
  - `rest_meditate`: 瞑想・エネルギー保存
* **`decide_growth_and_locus` (Choice/Noul)**: 捕食・分裂した個体の3D形態増殖と次の移動先を一括判断
  - 7種類の成長ベクトル（方位角・仰角）、分岐の起点（Anchor）、成長スケールを選択。
  - 捕食したページで見つかったリンクから、次に巡回する場所を選択。

## 2.5 健康モデル（成長・災厄・死）

3D形態のセル数が上限なく増え続けないよう、「大きな身体ほど維持コストがかかる」経済で growth と shrink を釣り合わせる。

1. **維持コスト**: 心拍のたびに、既存の細胞数 × 0.05 のエネルギーを消費する（`PER_CELL_UPKEEP`）。個体が大きくなるほど維持費が重くなり、無限成長を自然に抑制する。
2. **災厄（疫病・寄生虫）**: 細胞数が多い個体ほど、疫病または寄生虫に見舞われる確率が上がる（過密リスク）。発症すると、直近に生えた細胞を1〜3個失い、エネルギーも直接失う。
3. **回復には栄養が必要**: 失った細胞を取り戻すのも、新たに大きくなるのも、捕食（`ingest_nourish`）の成果からしか起こらない。ただし、現在の細胞数が過去の最高値（`peak_cells`）を下回っている間は、その最高値に戻るところまでしか増やせない（＝回復であって新規成長ではない）。最高値に追いつくと、その先の捕食は初めて `peak_cells` を更新する本当の成長になる。
4. **消滅**: エネルギーが0以下になると、その個体は世界から消える。世界の個体がすべて消滅した場合、次の心拍で新しい Ancestor-80 が自然発生する（既存の自動リポップ処理）。
